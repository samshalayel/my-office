## الكيانات (Entities)

### Subscriber — المشترك
- الحقول: id: UUID · name: string (إلزامي) · phone?: string (إن وُجد فريد [افتراض]) · area?: string (المنطقة/المحل) [افتراض] · monthlyFee: number > 0 · status: "active" | "suspended" | "cancelled" [افتراض — يحتاج قرار بشري] · joinedAt: ISODate · createdAt: ISODateTime
- القيود: id فريد · لا مشترك بلا name و monthlyFee · status لا يُكتب مباشرة — يُشتق من آخر StatusEvent
- العملة: ILS [افتراض — قرار بشري عند البوابة]
- العلاقات: 1 → N Payment · 1 → N StatusEvent

### Payment — الدفعة
- الحقول: id: UUID · subscriberId: UUID (إلزامي، يشير لمشترك موجود) · amount: number > 0 · monthKey: "YYYY-MM" (الشهر الذي تسدده الدفعة) · paidAt: ISODateTime · method: "cash" | "transfer" · ref?: string (مرجع/صورة إشعار التحويل) · note?: string
- القيود: append-only — لا حذف ولا تعديل (HR-3) · لا دفعة لمشترك غير موجود · المشترك الملغي لا يقبل دفعة إلا بعد إعادة تفعيله [قرار مقترح]
- العلاقات: N → 1 Subscriber

### StatusEvent — سجل تغيير الحالة
- الحقول: id: UUID · subscriberId: UUID · from: Status · to: Status · at: ISODateTime · reason?: string
- القيود: append-only (HR-3) · كل تغيير حالة لا بد له Event · الانتقالات المسموحة: active ↔ suspended · أي حالة → cancelled · هل cancelled نهائي؟ ⚠ يحتاج قرار بشري
- العلاقات: N → 1 Subscriber

### Statement — كشف الحساب (مشتق، غير مخزّن)
- الحقول: subscriber: Subscriber · payments: Payment[] · monthsUnpaid: "YYYY-MM"[] · arrears: number
- القاعدة: يُبنى لحظياً من السجلات فقط (ADR-5) · arrears = عدد الشهور غير المسددة × monthlyFee · حساب الملغي يتوقف عند شهر تغييره إلى cancelled · بداية العد من شهر الانضمام [افتراض — صيغة الشهر كامل/نسبي قرار بشري عند البوابة]

## القواعد الصارمة (Hard Rules)
| ID | القاعدة (قابلة للفحص نعم/لا) | المصدر |
|---|---|---|
| HR-1 | كل رقم يُعرض للإنسان مشتق من سجلات مخزّنة فقط — لا رقم يدوي ولا رصيد مخزّن | مقابل BR-3 من s1_skill — تكييف معلّم |
| HR-2 | لا إيقاف/تفعيل/تصنيف آلي — كل تغيير حالة إدخال بشري مسجل بسببه | NG-2 من s0_problem_lock |
| HR-3 | لا حذف ولا تعديل لسجل payment أو statusEvent — التصحيح بقيد معاكس مرئي | مقابل روح BR-6 من s1_skill — قرار مقترح على s2-gate-7 |
| HR-4 | لا رسائل واتساب ولا تنبيهات تلقائية | سجل الموافقة — F-6 خارج MVP |

## قرارات لا يعاد فتحها
> كلها مقترحات معمارية حتى اعتماد s2-gate-7. بعد الاعتماد: ممنوع على أي موديل لاحق اقتراح بديل.
- ADR-1: بلا backend — SPA + localStorage. السبب: مشغل واحد يحمل العمليات كلها (PD: شخص واحد يدير الشبكة)، والكشف يُعرض وجهاً لوجه (صياغة F-3)، ولا مزية لأي سيرفر بلا تعدد مستخدمين. جزء بيئة التشغيل [افتراض]. يحتاج تأكيد بشري.
- ADR-2: سجل الدفعات والحالات append-only مع قيود تصحيح معاكسة. السبب: أصل الأرقام لا يتشوه (HR-1/HR-3).
- ADR-3: monthKey صريح على كل دفعة («عن شهر») بدل استنتاج آلي من التاريخ. السبب: النظام لا يقرر بدل المشغل أي دفعة تسدد أي شهر (NG-2). [افتراض — تأكيد بشري]
- ADR-4: CSV بترميز UTF-8 مع BOM وأعمدة ثابتة. السبب: يفتح صحيحاً ب العربية في Excel. تفضيلي.
- ADR-5: لا حقول رصيد مخزّنة — الكشف مشتق لحظياً. السبب: رصيد مخزّن ينحرف عن السجلات ويكسر HR-1.
- إطار العمل الأمامي (React/Vanilla/…) غير مقفول في S2 — يُقفل في S3 بمبرر موثق، بلا تغيير للطبقات والعقود.

## مصطلحات المشروع (Glossary — يكمل S0/S1)
- المشترك (Subscriber): طرف يدفع اشتراكاً شهرياً مقابل خدمة الشبكة — له كشف حساب (F-1/F-3).
- دفعة لحظتها (Payment): تسجيل المبلغ لحظة استلامه — نقدي أو تحويل بمرجع (F-2).
- شهر الدفعة (monthKey): الشهر الذي تسدده الدفعة بصيغة YYYY-MM — قد يختلف عن تاريخ الدفع الفعلي.
- وسيلة الدفع (method): cash أو transfer — التحويل بلا مرجع موثق = أصل ناقص (نزاع «حولت وما وصل» من PD).
- كشف الحساب (Statement): عرض دفعات مشترك واحد + متأخراته — يُعرض أمام المشترك (F-3).
- المتأخرات (arrears): مجموع الشهور غير المسددة × monthlyFee — مشتق لحظياً وغير مخزّن.
- قيد معاكس: سجل تصحيحي بسببه يلغي أثر سجل سابق — بلا حذف (HR-3).
- سجل الحالة (StatusEvent): أثر مكتوب لكل تغيير active/suspended/cancelled مع سببه (F-4).
- المشغل الوحيد: مدير الشبكة — يستخدم النظام بلا حسابات دخول ولا صلاحيات (HR-6).
