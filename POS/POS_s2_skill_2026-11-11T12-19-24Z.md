## الكيانات (Entities)
- **Account** — طرف في السجل: `{ id: UUID, name: string (فريد داخل side), side: 'client' | 'supplier', ledgerTransfer: 'open' | 'completed', createdAt: ISODateTime }`
  - القيود: `side` ثابت بعد الإنشاء؛ الأسماء فريدة داخل كل اتجاه لتفادي حسم خلاف على اسم غامض؛ `ledgerTransfer: 'completed'` يعني اكتمال نقل رصيد الدفتر الورقي لهذا الحساب (س8-2) — لا يمنع أي عملية لاحقة.
  - الحجم المتوقع: ~250 عميلاً (client) و~20 مورّداً (supplier) [من S0 — لا افتراض فوقه].
  - العملاء والمورّدون أطراف عرض فقط — لا حساب دخول ولا مستخدم (NG-3).
- **Entry** — العملية الوحيدة في النظام: `{ id: UUID, type: 'debt_client' | 'debt_supplier' | 'payment_from_client' | 'payment_to_supplier' | 'cash_sale' | 'opening', accountId?: UUID, amount: number, ts: ISODateTime, note?: string, linkedTo?: UUID }`
  - القيود: `amount > 0` [تفصيل عرضٌه تحتاج تأكيداً بشرياً عند البوابة]؛ `accountId` إلزامي لكل الأنواع ما عدا `cash_sale` (BR-1, BR-8)؛ `type` صريح إلزامي — لا افتراض (BR-8)؛ لا يُعدَّل ولا يُحذف بعد الكتابة (BR-2)؛ `linkedTo` يُستخدم فقط في عملية تصحيح لتربطها بالأصل (BR-2).
  - دلالة الاتجاه: `debt_client`/`payment_from_client` على حساب عميل (يزيد/ينقص ما لي)، `debt_supplier`/`payment_to_supplier` على حساب مورّد (يزيد/ينقص ما عليّ).
- **DerivedBalance** — مشتق غير مخزَّن كمصدر حقيقة: `{ totalDebt: number, totalPaid: number, balance: number }` لكل حساب (BR-3, BR-4, BR-6). `balance` يسمح بالقيمة المعاكسة وفق BR-5 الافتراضي (س8-3 مفتوح).
- **DayLog** — عرض مشتق لا كيان مخزَّن: عمليات اليوم الواحد `ts ∈ [date 00:00, 24:00)` بالترتيب الزمني (F-10, C-7).

## المكونات ومسؤولياتها
| المكوّن | الطبقة | المسؤولية الوحيدة | ما لا يفعله |
|---|---|---|---|
| AppShell | UI | هيكل PWA والتنقل بين الشاشات الأربع | لا يتحقق من بيانات ولا يحسب أرصدة ولا يعرض شاشة دخول |
| AccountsDashboard | UI | عرض «ما لي»/«ما عليّ» بأرصدة لحظية + بحث (F-5, F-6) | لا يعدّل بيانات ولا يحسب بنفسه |
| AccountLedgerView | UI | شاشة حساب الطرف: الثلاثية وسجل الحركات، وتُعرض كدليل (F-7, SC-5) | لا يعدّل العمليات |
| QuickEntryForm | UI | إدخال عملية واحدة بأقل من دقيقة بنوع صريح (F-1, F-4, F-10) | لا يكتب مباشرة على التخزين — يعبر EntryValidator |
| DayLedgerView | UI | عرض سجل حركة اليوم (F-10) | لا يفرّق الأرصدة ولا يمس الدفترين |
| OpeningMigrationPanel | UI | قيد افتتاحي وإقفال نقل الحساب (F-9, س8-2) | لا ينقل كل الحسابات دفعة واحدة ولا يعدل أرصدة سابقة |
| EntryValidator | Logic | التحقق من صلاحية العملية قبل الكتابة | لا يكتب ولا يحسب أرصدة |
| BalanceCalculator | Logic | احتساب DerivedBalance وDayLog وسجل الحساب من العمليات | لا يقرأ من أي مصدر غير LedgerStore، ولا يقبل رقماً يدوياً |
| SearchProvider | Logic | البحث والاختيار السريع ضمن ~270 حساباً | لا ينسخ الحسابات ولا يعدلها |
| LedgerStore | Data | الوحيد الذي يقرأ/يكتب السجل append-only | لا يحتسب أرصدة ولا يعرف قواعد عرض |
| LocalDatabase | Data | IndexedDB محلي (accounts / entries / meta) | لا يتصف شبكة ولا يخزن رصيداً كمصدر |

## القواعد الصارمة (Hard Rules)
| HR | القاعدة (قابلة للفحص نعم/لا) | المصدر |
|---|---|---|
| HR-1 | كل البيانات تُخزن محلياً على الجهاز فقط؛ صفر استدعاء شبكة في مسار أي عملية قيد/تسديد/عرض | BR-7, K-4, NG-4, K-1 |
| HR-2 | مصدر الحقيقة الوحيد سجل العمليات؛ لا رصيد يُخزن كمصدر مستقل — أي مُسوّد للعرض يُبنى من السجل وإعادة بنائه الكلية تعطي نفس الأرقام حرفياً | BR-3, BR-6 |
| HR-3 | أي عملية مكتوبة لا تُعدَّل ولا تُحذف — التصحيح عملية جديدة مرئية ترتبط بالأصل | BR-2, SC-5 |
| HR-4 | لا عملية دين/تسديد/افتتاحي بلا حساب طرف؛ الاستثناء الوحيد `cash_sale` | BR-1, BR-8 |
| HR-5 | نوع العملية صريح إلزامي في كل عملية — لا افتراض نقدي/أجل صامت | BR-8 |
| HR-6 | مستخدم واحد بلا تسجيل دخول ولا صلاحيات ولا تفويض ولا تعدد أجهزة مُتزامنة | NG-3, K-2 |
| HR-7 | لا حقول ولا بنية لمخزون أو تلف أو أرباح أو محاسبة — حتى كحقول احتياطية «للمستقبل» | NG-1, NG-2 |
| HR-8 | كل رقم يظهر على الشاشة يُحتسب من السجل — لا قيمة ثابتة مكتوبة في الواجهة | BR-6 |
| HR-9 | النقل الافتتاحي تدريجي: حساباً حساباً، والحساب يُقفل عند اكتمال نقله — لا إجبار نقل دفعة واحدة | س8-2, F-9 |
| HR-10 | الحساب يسمح بالقيمة المعاكسة وفق BR-5 الافتراضي — أي منع مستقبلي يكون حاجباً أعلى (UX) بقرار إنسان، لا تغيير بنية | س8-3, BR-5 |
| HR-11 | كل شاشة أساسية تعمل بلا اتصال وبلا خطوات دخول قبل أي عملية | BR-7, K-4 |

## قرارات لا يعاد فتحها
- **ADR-1**: PWA أوفلاين-أولاً بلا خادم خلفي — حدده الإنسان بنفسه (K-4/Q-5) ويحفظ NG-4/K-1. (تفصيل خطر بيانات الجهاز الواحد يحتاج قراراً بشرياً لاحقاً — خارج MVP ولا يُبنى عليه الآن.)
- **ADR-2**: التخزين المحلي IndexedDB خلف طبقة LedgerStore — السجل التراكمي بحركة يومية (U-7) واستعلامات بحسب الحساب/اليوم يستلزمان فهارس.
- **ADR-3**: نموذج ledger-only: الأرصدة مشتقة دائماً (BR-3, BR-6) — لا حقل رصيد مُصدر.
- **ADR-4**: التصحيح عملية جديدة مرئية ترتبط بالأصل (BR-2) — لا تعديل في المكان ولا حذف.
- **ADR-5**: ستة أنواع عمليات صريحة فقط: `debt_client, debt_supplier, payment_from_client, payment_to_supplier, cash_sale, opening` (BR-1, BR-8).
- **ADR-6**: بنية الرصيد تسمح بالقيمة المعاكسة بحيث يبقى تبديل BR-5 لاحقاً قراراً بسيطاً بلا إعادة معمارية (س8-3).
- **ADR-7**: النقل الافتتاحي تدريجي مع علم إقفال لكل حساب (س8-2).
أي موديل لاحق ممنوع يقترح بديلاً لهذه السبعة إلا عبر ملحق قرار إنساني جديد.

## مصطلحات المشروع (Glossary — يكمل S0/S1)
- «ما لي» / «ما عليّ»: الدفتران — ما على العملاء (client) وما على صاحب المتجر لمورّديه (supplier).
- «الثلاثية»: `totalDebt / totalPaid / balance` — تظهر دائماً معاً لكل حساب (BR-3, SC-4).
- «سجل حركة اليوم»: عرض مشتق لعمليات اليوم الواحد — شريط النقدي المعتمد حديثاً (F-10) يظهر فيه دون أي أثر على الدفترين (BR-8, AC-8).
- «عملية تصحيح»: Entry من نوع تصحيحية ترتبط بـ `linkedTo` بعملية أصل تبقى ظاهرة بعلامة «مُصحّح» — لا محو صامت (BR-2).
- «النقل التدريجي»: إدخال رصيد افتتاحي حساباً حساباً ثم إقفاله بـ `ledgerTransfer: 'completed'` (س8-2).
- «append-only»: إضافة فقط على سجل العمليات — لا تعديل ولا حذف (HR-3).
- «المُسوّد المحسوب»: قيمة عرض مشتقة من السجل يمكن إسقاطها وإعادة بنائها — ليست مصدر حقيقة (HR-2).
