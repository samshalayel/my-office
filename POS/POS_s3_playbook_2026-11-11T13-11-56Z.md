## 1. استراتيجية التقسيم

قرار: **تقسيم متعدد الشرائح** — مكوّنات `s2-components-3` الـ 11 تنقسم إلى 5 شرائح عمودية قابلة للتسليم end-to-end، مع شريحة أساس إلزامية `base` (وُجد كيانان معتمدان في S2 — Account وEntry — وبنود BASE منطبقة).

- **Foundation = base**: التخزين المحلي + CRUD الحسابات + بنود الأساس + هيكل PWA أوفلاين (AppShell + Service Worker). كل شرائح الألم تقف عليه.
- **المفتاح المشترك**: سجل العمليات append-only عبر LedgerStore حصراً — لا واجهة تلمس IndexedDB مباشرة، ولا استدعاء شبكة في مسارات القيد والتسديد والعرض (HR-1, BR-2, BR-6).

## 2. خريطة التبعيات

```
base (Foundation)
  ├→ entry (يعتمد على base)
  │     ├→ views (يعتمد على base + calc + entry)
  │     └→ migr (يعتمد على base + entry)
  └→ calc (يعتمد على base)
```

لا دورات — entry وcalc تعملان بالتوازي بعد اكتمال base.

## 4. نقاط التوقف الإلزامية
1. **بعد اكتمال Foundation** (base كاملة — 15 مهمة) قبل بدء أي شريحة ألم.
2. **قبل بدء كل مهمة 👤** (6 مهام): base-T14, base-T15, entry-T1, entry-T2, calc-T1, migr-T1.
3. **قبل شريحة migr**: أول لمس لبيانات حقيقية من الدفتر الورقي — وقبل إقفال النقل (ledgerTransfer=completed) لأول حساب.
4. عند أي حاجة لتغيير توقيع أو إضافة dependency → توقف وارفعها DEV-N للإنسان.
5. **قبل إعلان اكتمال [base-T15]**: لا يُقبل بلا استعادة مُجرَّبة فعلياً من النسخة السحابية المشفّرة.
