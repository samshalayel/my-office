> للإنسان: استراتيجية التقسيم والتبعيات والخطة ونقاط التوقف. المدخل: حزمة S2 المعتمدة (بوابة s2-gate-7 — اعتمادك موثق في JSON وcommit 140a8bd بتاريخ 2026-11-20) + decisions.md (DEC-1..DEC-18 كلها موقعة).

## 1. استراتيجية التقسيم
**القرار: قالب متعدد الشرائح (Multi-Slice)** — مكونات S2 منفصلة الواجب: طبقة أساس مشتركة، ثم أدوات، ثم وكيل، ثم واجهة قرار إنساني، ثم اختبار — كل وحدة تُسلَّم وتُختبر end-to-end منفصلة. المفتاح المشترك: كل شيء يمر عبر base (trace/سقوف/audit/أسرار). القرارات المقفلة حكمت التقسيم: DEC-11 أ (بلا إطار → لا شريحة "إطار") · DEC-14 أ + DEC-15 أ (خادم داخل المشفى + SQLite → لا شريحة سحابة ولا قاعدة موزعة) · DEC-16 أ (واجهة ويب داخلية → شريحة hitl مستقلة) · DEC-13 ب (إخفاء الهوية → مهمة داخل agent لا شريحة أمن منفصلة) · DEC-17 أ (منع عند الحد → الحمايات مبنية مع العنصر الذي تحميه).

## 2. خريطة التبعيات
```
base (Foundation)
  ├→ tools (يعتمد على base)
  │    ├→ agent (يعتمد على base + tools)
  │    │    └→ hitl (يعتمد على base + tools + agent)
  └────────┴─────────┴→ verify (يعتمد على الكل)
```
تبعيات محورية: agent-T1 يبدأ بعد base-T3 (تتبّع) + base-T5 (مفتاح إيقاف) + tools-T1 (قراءة) + tools-T8 (تحقق كتابة) — لا حلقة بلا تتبّع وسقوف وحمايات كتابة. كل RT-N تعتمد على مهمة MIT التي تختبرها حصراً (verify-T4 يعتمد على agent-T9 + base-T5 معاً لأنه يختبر السقف والمفتاح).

## 4. نقاط التوقف الإلزامية
1. **بعد اكتمال شريحة base كاملة** — مراجعة قبل بدء tools (لا وكيل بلا تتبّع وسقوف وأسرار).
2. **قبل tools-T1: أول اتصال ببيانات حقيقية من سجلات المشفى** — موافقة صاحب الحضانة إلزامية (بيانات صحية — K-2).
3. **كل مهمة 👤** — القائمة الكاملة: base-T4/T5/T6/T10 · tools-T2/T6/T7/T8 · agent-T2/T9 · hitl-T1/T2/T4/T5/T7/T9 · verify-T9.
4. **قبل فتح الواجهة (hitl) على بيانات حقيقية** — مراجعة الواجهة نفسها وهي نقطة القرار الإنساني.
5. **عند أي حاجة لتغيير توقيع C-N أو إضافة dependency** → توقف وارفع DEV-N — التواقيع ملزمة من S2.
6. **verify-T9 (المراجعة الأمنية النهائية)** قبل إعلان جاهزية بوابة S3.
7. TH-7/TH-8 (MIT-9/MIT-8) مقبولة بمراقبة وفق قرار S2 — تنتقل إلى RISK-N في S6.

## 5. معايير Slice Gate (s3-gate-7)
تطابق 1:1 بين JSON وCSV (48 مهمة بنفس الأسماء والترتيب)؛ كل C-1..C-15 مغطاة بمهمة؛ كل AGT/TL/HITL/END من S1 له مهمة؛ كل MIT-1..MIT-9 لها مهمة تنفيذ (👤 security) وRT-1..RT-6 لما خططت S2 اختباره هجومياً (MIT-8/MIT-9 مراقبة وفق قرار S2)؛ كل EV-1..EV-8 له حالة في المشغّل؛ شريحة base فيها BASE-A1/A2/A7/A8 ومشغّل التقييم قبل أول وكيل؛ لا دورات في التبعيات وFoundation محددة؛ المهام الحرجة 👤 بوسم human-review؛ لا أداة تنفيذ ولا إطار غير مقرر (DEC-9/DEC-11)؛ التواقيع منسوخة حرفياً من S2.
